# ME-Control (OC-Terminal)

Панель управления МЭ-сетью (Applied Energistics 2) для OpenComputers.

## 🚀 Возможности
* Просмотр МЭ-сети и инвентаря игрока (через PIM).
* Выдача и сдача предметов (включая NBT-предметы).
* Поиск по названию (с поддержкой кириллицы).
* Сортировка списка по клику на заголовок: А-Я / по убыванию / по возрастанию.
* Горячие клавиши: F1–F6 — вкладки, `/` — быстрый поиск.
* Система ролей: Guest / User / Moderator / Admin / TechAdmin (иерархия прав).
* Персональные права: забор / сдача / крафт — включаются отдельно каждому игроку.
* Баны с указанием причины и срока.
* Логи операций (кто, когда и что сдал/забрал).
* Журнал операций: ровные колонки, фильтр по типу (1/2/3), очистка для админа.
* Единый стиль сообщений: `[OK]` / `[ОШИБКА]` / `[ВНИМАНИЕ]`.
* Всплывающие уведомления (toasts) в правом верхнем углу на 4 секунды.
* Мониторинг запасов с оповещениями (редстоун + звук).
* Статистика МЭ-сети: предметы, типы, энергия, занятость дисков (байты и типы).
* График энергии («кардиограмма») за последние 40 секунд.
* Приход и расход энергии (AE/t) с предупреждением о дефиците.
* Автокрафт по лимитам: при просадке ниже минимума панель сама заказывает недостающее.
* Показатели крафт-процессоров (занято / всего) и время работы компьютера.
* Цветовые маркеры категорий предметов в списках (слиток / руда / пыль / еда).
* Крафт: список доступных рецептов и отправка запроса на изготовление.
* Текстовый редактор `medit.lua` (создание и правка `.lua` прямо на компьютере).
* Красивый GUI с прогресс-барами и «зеброй».

## 💾 Ёмкость хранилища

На вкладке «Статистика» показывается занятость дисков. В большинстве сборок OC 1.7.10
у `me_interface` нет метода `getCells()`, поэтому общий объём сети неизвестен —
панель показывает только занятый объём с пометкой «оценка занятого».

Чтобы видеть точный прогресс-бар с процентами, укажите ёмкость вручную в `config.lua`:

```lua
config.storage = {
    -- Общая ёмкость МЭ-сети в байтах (например, 4 ячейки по 4k = 16384).
    totalBytes = 16384
}
```

Оставьте `nil` — будет использоваться автоматическая оценка.

| `F2` | Инвентарь |

Коды клавиш взяты из `lib/core/full_keyboard.lua` OpenOS: `F1=59 … F6=64`, `/ = 53`.
Если Minecraft перехватывает какую-то из F-клавиш (например `F3` — экран отладки,
`F5` — смена вида), вкладку всегда можно выбрать мышью.

## 🔨 Крафт

Вкладка «Крафт» показывает все известные МЭ-сети рецепты (`me.getCraftables()`).
Тапните по предмету — откроется окно «Запрос на крафт» с кнопками `-10 / -1 / +1 / +10`
и зелёной кнопкой «СКРАФТИТЬ». Строка «В сети:» показывает, сколько этого предмета
уже лежит в сети.

Запрос уходит в МЭ через `craftable.request(amount)`; если свободного сопроцессора нет,
в статус-баре появится текст ошибки от МЭ.

После отправки панель следит за статусом крафта (`isDone` / `isCanceled` / `hasFailed`,
если метод есть) раз в 2 секунды и пишет в статус-бар:

* `Крафт завершен!` — предметы готовы;
* `Крафт отменен` — запрос отменён в МЭ;
* `Крафт провален (возможно, не хватает ресурсов или CPU занят)` — ошибка.

Если `me_interface` не поддерживает `getCraftables()`, список будет пустым —
вкладка при этом не ломает панель.

### Диагностика крафтов

Если вкладка «Крафт» пустая, запустите отдельный скрипт:

```bash
test_craft.lua
```

Он покажет: есть ли `me_interface`, что лежит в `me.getCraftables`
(`type` и `getmetatable`, включая `__call`), текст ошибки вызова, длину списка
и структуру первых трёх рецептов (`name`, `label`, `damage`, `size`).

Метод вызывается напрямую (`me.getCraftables()`), без проверки `type(...) == "function"`:
в OpenComputers прокси-метод может быть таблицей с метаметодом `__call`,
и такой объект тоже вызывается. Если объект не вызывается вовсе, панель сообщит
`getCraftables: table без __call`.

Причина последней неудачи также сохраняется в `_G.last_craft_error`
и выводится в статус-бар панели: `Крафты не найдены. Ошибка: …`.

### Автокрафт по лимитам

Если на вкладке «Монитор» задан минимум (лимит) и предметов в сети стало меньше,
панель сама заказывает недостающее — без участия игрока.

* Проверка лимитов выполняется раз в **10 секунд**.
* Предмет должен быть доступен как рецепт (`me.getCraftables()`).
* За один запрос заказывается `min − current`, но не больше **1 стака (64 шт)**.
* На один и тот же предмет действует пауза **60 секунд** (`state.lastAutoCrafts`),
  чтобы не заваливать МЭ запросами.
* Если процессор занят (запрос не удался) — панель молча ждёт следующей проверки
  и не спамит ошибками.
* При успешном запросе всплывает уведомление `Автокрафт: запущен <предмет> x<N>`.

Настройка в `config.lua`:

```lua
config.autoCraft = {
    enabled = true,   -- выключить автокрафт целиком
    interval = 10,    -- период проверки лимитов, сек
    cooldown = 60,    -- пауза между запросами на один предмет, сек
    maxStack = 64,    -- максимум за один запрос
}
```

Автокрафт — системная операция компьютера: он не требует, чтобы на PIM стоял
игрок с правом `canCraft` (в отличие от ручного заказа на вкладке «Крафт»).
Отправка идёт через `api.autoCraft()`.

### Диагностика энергии

Если в статистике нет данных об энергии, запустите:

```bash
test_energy.lua
```

Скрипт перебирает энергетические компоненты (`me_controller`, `energy_acceptor`
и др.), печатает их методы, вызывает типовые (`getEnergyStored`, `getStoredPower`,
`getAverageInsertion`, …) через `pcall` и в конце выдаёт:

```
ИТОГ: Энергия = 12500 / 20000 (63%)
Источник: me_controller (ctrl-0001)
Методы:   getStoredPower() / getMaxStoredPower()
```

Если ни одна пара «занято / всего» не сработала, скрипт подскажет, что нужен
адаптер вплотную к ME Controller.

## 🔄 Обновление

Файл `version.txt` хранит текущую версию. `getcode.lua` читает его до скачивания
и после — и печатает результат:

```
=== ГОТОВО ===
Успешно: 8 | Ошибок: 0
Общий размер: 342.1 KB
Время выполнения: 12.44 сек.
ОБНОВЛЕНИЕ: v1.4.1 -> v1.4.2
Все файлы обновлены до последней версии!
Запускайте: main.lua
```

Возможные варианты последней строки:
* `Текущая версия актуальна: v1.4.2` — версии совпали;
* `Установлена версия: v1.4.2` — первая установка (файла не было);
* `ОБНОВЛЕНИЕ: v1.4.1 -> v1.4.2` — версия изменилась.

## 📊 Статистика и маркеры

На вкладке «Статистика» панель показывает:

* количество предметов и типов (все количества округляются вниз до целых);
* энергию с прогресс-баром и **однострочным графиком** за последние 20 замеров
  (≈40 секунд), по одному символу на замер по шкале `▁▂▃▄▅▆▇█`
  (8 уровней по 12.5%: от 0 до 100%). Полоса заполнения и график всегда
  находятся на соседних строках и не перекрывают друг друга:
* занятость дисков в байтах и типах;
* **приход и расход энергии** в AE/t:

  ```
  Приход: +120 AE/t     Расход: -300 AE/t
  [!] Дефицит энергии!
  ```

  Строка прихода окрашена зелёным, расхода — красным; если расход превышает
  приход, ниже выводится предупреждение о дефиците. Данные берутся из
  `getAvgPowerInjection()` / `getAvgPowerUsage()`;
* **Крафт-процессоры: занято / всего**;
* сопроцессоры и **время работы компьютера** (`ЧЧ:ММ:СС`).

В списках МЭ-сети, инвентаря и крафтов перед названием появляется цветной маркер:

| Маркер | Категория | Слова в названии |
|---|---|---|
| 🟨 `■` | слитки | `ingot`, `слиток` |
| ⬜ `■` | руды | `ore`, `руда` |
| 🟥 `■` | пыль | `dust`, `пыль` |
| 🟩 `■` | еда | `food`, `apple`, `bread`, `яблоко`, `хлеб`, `мясо`, `рыба` |

Сырые ключи локализации автоматически «раскрываются»: название вида
`item.appliedenergistics2.ItemMaterial.CardAdvSpeed.name` показывается как
`CardAdvSpeed`, а `minecraft:oak_planks` — как `Oak Planks`.

## 📜 Журнал операций

Вкладка «Журнал» (F5, только для администратора) показывает операции ровными колонками:

```
Время    | Игрок        | Действие  | Предмет                   |   Кол-во
15:05:07 | lixynhay     | Сдал      | Iron Ingot                |      512
15:04:02 | Steve        | Взял      | Медный слиток             |       64
```

* «Сдал» подсвечивается зелёным, «Взял» — жёлтым.
* Фильтр по типу: клавиши `1` (все), `2` (только выдача), `3` (только сдача)
  или клик по кнопкам в строке «Фильтр:».
* Поиск по игроку/предмету — клавиша `/`.
* Кнопка **«ОЧИСТИТЬ»** (только админ) требует подтверждения: первый клик
  превращает её в «ТОЧНО?», второй — очищает журнал.

## 🛡️ Роли и права

Иерархия ролей (`db.ROLE_LEVELS`) — управлять можно только теми, кто **строго ниже**:

| Уровень | Роль | Возможности |
|---:|---|---|
| 0 | `banned` | заблокирован |
| 1 | `guest` | только смотреть |
| 2 | `user` | брать / сдавать / крафтить |
| 3 | `moderator` | банить юзеров и ниже |
| 4 | `admin` | менять роли и персональные права |
| 5 | `techadmin` | всемогущий |

Правила `db.hasPermission(actor, target, action)`:
* нельзя действовать на себя;
* уровень актора должен быть строго выше уровня цели;
* `ban` — с уровня `moderator`, `setRole`/`setPermission` — с уровня `admin`.

Каждый игрок имеет персональные флаги `canWithdraw`, `canDeposit`, `canCraft`
(по умолчанию `true`). Проверяются и в интерфейсе, и в `me_api`
(`exportToPlayer`, `pushFromPlayer`, `depositAll`, `requestCraft`).

В карточке игрока (Админка) есть три тумблера:

```
Права:   [ ЗАБОР:ВКЛ ]   [ СДАЧА:ВЫКЛ ]   [ КРАФТ:ВКЛ ]
```

Плюс кнопки `ЗАБАНИТЬ`, `РОЛЬ` (цикл guest → user → moderator → admin),
`РАЗБАН`, `ЗАКРЫТЬ`.

Карточка также показывает статистику профиля и историю:

```
Статистика:
Всего действий:      42
Последняя активность: 01.01 05:02

Последние 5 действий:
  [01.01 05:02] Сдал 64x Iron Ingot
  [01.01 05:01] Взял 3x Diamond
```

«Сдал» подсвечивается зелёным, «Взял» — жёлтым. Данные берутся из
`db.getLogsForPlayer(name, 5)`, счётчик `totalActions` и `lastSeen`
обновляются в `db.addLog`.

## 🔔 Уведомления

Важные события (выдача, сдача, крафт, бан, смена роли/прав) дублируются
плавающими плашками в правом верхнем углу. Плашка живёт 4 секунды,
рамка окрашена по типу: `[+]` зелёный успех, `[!]` красный/жёлтый — ошибка
или предупреждение.

```
╔══════════════════════════╗
║ [+] Выдано: 64 шт.       ║
╚══════════════════════════╝
```

## 📝 Текстовый редактор `medit.lua`

Отдельная утилита для правки файлов прямо на компьютере (не требует МЭ-сети).
Файл входит в `manifest.txt`, поэтому скачивается через `getcode.lua`
вместе с остальными.

```
medit test.lua
```

Экран делится на две части: слева — поле номеров строк (ширина 4, приглушённый
цвет `C.muted`), справа — область ввода. В самом низу, на строке `H`, —
статус-бар:

```
Стр: 1, Кол: 6 | Файл: test.lua | Ctrl+S - Сохранить, Ctrl+Q - Выйти
```

Курсор выделяется инверсией цвета фона. Текст хранится массивом строк.

| Клавиша | Действие |
|---|---|
| `↑` `↓` `←` `→` | перемещение курсора |
| `PageUp` / `PageDown` | постранично вверх / вниз |
| `Home` / `End` | в начало / конец строки |
| `Enter` | перенос строки |
| `Backspace` / `Delete` | удаление символа (с поддержкой UTF-8, включая кириллицу, через `unicode.sub`) |
| `Tab` | вставка 4 пробелов |
| обычные символы и цифры | ввод текста |
| `Ctrl+S` | сохранить файл в текущую директорию |
| `Ctrl+Q` / `Esc` | выйти (при несохранённых правках запрашивает подтверждение) |

Если файл существует — он загружается при запуске, иначе редактор открывается
с чистого листа. Палитра берётся из `config.colors`; если `config` недоступен,
используется встроенная.
